# 契约 · Python 函数工具

三个子 Agent(治理审计、运维发布、服务验证)**不声明 `os_env`**,因此没有 shell、没有文件工具,**跑不了任何脚本**——skill 的 `scripts/` 目录对它们形同虚设。它们所需的一切确定性逻辑,**只能以 Python 函数工具提供**(FR-095)。

## 声明形态

```yaml
tools:
  <tool_name>:
    type: function
    description: <给模型看的用途说明>
    callable: omnigent.tools.pipely.<module>.<callable>
    parameters:
      type: object
      properties: { ... }
      required: [ ... ]
```

## 强弱边界

函数工具**保证"做的时候按代码做",保证不了"一定会做"**——是否调用由模型决定。因此凡是"必须做且必须做成"的要求,工具必须与策略配对:策略在 `tool_result` 上读**工具的真实返回值**并写标签,后续操作在 `tool_call` 上凭标签放行(FR-097)。

工具的返回结构因此是**硬契约**:策略要按字段判定,字段变了策略就失灵。

## 工具清单

### `verify_governance` —— 只读核验治理落地

承载 FR-017、FR-019;其返回值是 `g2_passed` 标签的**唯一合法来源**。

**入参**:变更请求包标识(定位状态断言)

**返回**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `passed` | bool | 全部断言是否通过 |
| `assertions` | 列表 | 每项含断言、期望值、**实际值**、判定 |
| `missing_steps` | 列表 | 未通过时需补做的具体步骤(FR-018) |

**约束**:
- **只读**——治理审计 bot 的凭证与工具集从结构上不具备写能力(FR-011)
- **幂等**——重复核验结果一致且无副作用(FR-019)
- 失败项必须指明**期望值与实际值**,不能只给"不通过"

### `quality_gate` —— 质量门禁判定

承载 FR-027、FR-028。

**入参**:制品引用(内含该版本**冻结的质量阈值**)、本次运行的实测结果

**返回**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `passed` | bool | 全部门禁项是否通过 |
| `items` | 列表 | 每项含门禁项、**实际值**、阈值、判定 |

**约束**:门禁项至少覆盖记录数、异常率、结构一致性、黄金用例结果、查询性能;**每项必须输出实际值与阈值的对比**——只给"通过/不通过"不可接受,"刚好通过"会被误当作无风险。

阈值来自制品引用而非仓库:运维发布 Agent 无 shell、读不了仓库(FR-101)。

### `bot_selfcheck` —— bot 权限自检

承载 FR-074、FR-075;是 `pipely.preflight` 标签的来源。

**入参**:待检 bot 清单及各自应有权限

**返回**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `passed` | bool | 全部 bot 权限是否符合预期 |
| `probes` | 列表 | 每项含 bot、探测动作、**是否被拒**、拒绝原因 |
| `over_privileged` | 列表 | 权限宽于职责的具体项 |

**关键约束——必须含负向探测**:只读 bot 的**写操作探测被拒绝**才算通过;仅验证"令牌可用"**不算**通过(FR-074)。理由:一个被误授写权限的只读 bot **不会有任何症状**,FR-011 会悄无声息地失效。

负向探测必须选**无害动作**(如对一个不存在的对象发起写请求),确保即便意外未被拒也不产生实际变更。

## 测试契约

工具是纯函数,单测构造入参断言返回值。三条必须覆盖的负向用例:

1. `verify_governance` 在断言不满足时,`passed=False` 且 `missing_steps` 非空
2. `quality_gate` 在任一项未达阈值时,`passed=False` 且该项的实际值与阈值都在 `items` 里
3. `bot_selfcheck` 在只读 bot 的写探测**未被拒**时,`passed=False` 且该 bot 出现在 `over_privileged` 中

第 3 条是最容易漏的——它测的是"检查器本身有没有用"。只会说"没问题"的检查器毫无价值。

测试落 `tests/tools/pipely/`。
